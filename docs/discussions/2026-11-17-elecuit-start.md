# elecuit 시작

## 질문

- 전기전자 전공자가 GPT 같은 LLM에게 회로를 물으면 그림이 자주 틀린다. 틀리지 않게 하는 조작 가능한 템플릿을 만들 수 있는가.
- 화면 안의 모든 표시는 KaTeX를 지원해야 한다.

## 확인한 사실

- 사용자가 보여 준 LLM 그림(1-3 domino 게이트에 X precharge 추가)에서 `Y` 가로선이 precharge PMOS의 VDD 세로선에 닿아 `Y`가 VDD에 단락되어 있었다.
- 원인은 LLM이 좌표를 직접 찍는 데 있다. 좌표만으로는 "선이 지나간다"와 "선이 연결된다"가 구분되지 않는다.
- CircuitikZ와 schemdraw는 배치를 LLM이 정하므로 같은 종류의 실수를 막지 못한다. schemdraw 라벨은 KaTeX가 아니다.

## 결정

1. LLM은 좌표 없이 소자와 노드 이름만 쓰는 netlist를 낸다. 연결은 노드 이름이 같은지로만 정한다.
2. 렌더러가 배치를 계산한다. VDD–GND 사이를 직렬·병렬로 분해해 스택으로 그리고, 선은 기하적으로 겹치지 않음이 보장되는 곳에만 긋고 나머지는 노드 이름 라벨로 잇는다.
3. 첫 범위는 CMOS 트랜지스터 회로(`nmos`, `pmos`), 논리 게이트 기호(`inv`, `buf`, `nand`, `nor`, `and`, `or`), `cap`이다.
4. 화면은 붙여 넣는 단일 웹 페이지이고, 편집은 텍스트와 실시간 미리보기로 한다.
5. 사용자 요청으로 이 프로젝트는 하우스 디자인 스타일과 시안 승인 절차를 쓰지 않고, 에이전트가 고른 디자인으로 만든다.
6. 브라우저 전용 Vite 앱을 하나의 HTML 파일로 빌드해, 설치 없이 열 수 있게 한다.

## 2026-11-17 채팅 안 미리보기

### 질문

- 붙여 넣기 대신, GPT가 답할 때 HTML 미리보기로 회로도를 바로 띄울 수 있는가. HTML 소스에 데이터만 주입하는 방식이면 되는가.

### 확인한 사실

- ChatGPT의 Canvas 미리보기는 GPT가 직접 쓴 HTML만 보여 주므로, 1.8MB 단일 HTML에 데이터만 바꿔 넣는 방식은 쓸 수 없다.
- 사용자가 ChatGPT Canvas에서 jsdelivr의 KaTeX 스크립트와 스타일을 불러오는 HTML을 시험했고, 수식이 정상으로 보였다. Canvas는 외부 CDN 스크립트를 실행한다.
- npm에 `elecuit`이라는 패키지 이름은 비어 있다.

### 결정

1. 렌더러를 스크립트 하나(`dist/elecuit.js`)로 묶는다. 호스트 페이지의 `<script type="text/elecuit">` 블록마다 회로도, 검사 결과, 노드 연결 정보를 그린다.
2. netlist는 `<script type="text/elecuit">` 블록에 둔다. 수식의 `<` 같은 글자가 HTML로 해석되지 않게 하기 위해서다.
3. KaTeX 스타일과 글꼴은 번들에 넣지 않고 jsdelivr에서 번들의 KaTeX와 같은 버전으로 불러온다.
4. GPT는 짧은 템플릿에서 netlist 블록만 바꿔 쓴다. 지침 문구는 `canvasPrompt`가 만든다.

### 보류

- 번들을 올릴 곳(npm 공개 패키지 등)과, 그 URL을 넣은 지침 복사 버튼.

## 2026-11-17 여러 회로 배치

### 질문

- 회로 여러 개를 격자(n열·n행)로 그리거나, 위에 버튼을 두어 탭으로 넘겨 보게 할 것인가.

### 확인한 사실

- 임베드는 블록마다 그림을 그 블록 바로 아래에 넣어, 여러 회로가 세로로만 쌓였다.
- 배율을 회로마다 미리보기 폭에 따로 맞춰, 좁은 회로는 크게 넓은 회로는 작게 그려졌다. 원래 회로와 개선 회로를 비교하면 같은 소자의 크기가 달랐다.
- 모델은 미리보기의 폭을 알 수 없다. 폭은 렌더러가 그릴 때 안다.

### 결정

1. 사이에 공백과 주석만 두고 연달아 쓴 블록을 한 묶음으로 본다. 블록 사이에 다른 요소가 있으면 묶음이 나뉜다.
2. 한 묶음은 격자로 놓는다. 열 수는 렌더러가 정한다. 모든 회로를 한 줄에 놓는 것부터 열을 하나씩 줄여 가며, 배율이 0.7 이상이 되는 가장 많은 열을 고른다. 열 수를 모델이 지정하는 문법은 두지 않는다.
3. 한 묶음의 회로는 배율 하나를 함께 쓴다. 배율은 1.25를 넘지 않고, 한 열만 남으면 폭에 맞게 0.7 아래로도 줄인다.
4. 블록의 `title` 속성을 회로도 위에 제목으로 보인다. `$…$`로 감싼 부분은 KaTeX로 그린다.
5. 지침 문서의 템플릿에 `title`을 넣고, 여러 회로는 연달아 쓰게 한다. 설명 문단은 묶음의 앞뒤에 둔다.
6. 배치 계산은 `src/web/lib/arrange.ts`에 두고 단위 테스트로 확인한다.
7. version을 `0.2.0`으로 올린다.

### 보류

- 탭으로 하나씩 넘겨 보는 방식. 회로를 4개 이상 그리는 일이 생기면 다시 본다. 넣더라도 모델이 고르는 문법이 아니라 보는 사람이 누르는 버튼으로 둔다.
- 붙여 넣는 페이지에서 회로 여러 개를 그리는 것.
- 브라우저에서의 화면 확인. 묶음을 나누는 판단과 격자 배치는 DOM에 달려 있어 단위 테스트가 닿지 않는다.

## 2026-11-17 범용 회로와 2차원 배치

### 문제

- 사용자가 `0.1.3`으로 그린 1-bit ALU(게이트 46개와 domino carry)가 한 줄로 길게 늘어져 읽을 수 없었고, domino carry 단은 "직렬·병렬 구조가 아니라 소자별로 따로 그렸다"는 안내와 함께 흩어졌다.
- 사용자 요청: 안 되는 것을 고치고, 전기전자공학부에서 다루는 범용 회로를 표현할 수 있게 한다(초고집적 제외).

### 확인한 사실

- 기존 배치는 모든 단과 게이트를 한 행에 차례로 놓았다. 소자 60개짜리 회로의 폭이 높이의 약 40배가 됐다.
- 기존 배치는 VDD와 GND 사이가 직렬·병렬로 분해될 때만 스택으로 그렸다. domino carry 단은 내부 노드 둘(X1N, X2N)에 precharge 트랜지스터가 하나씩 붙어 분해되지 않는다.
- 문법에는 MOS, 게이트 6종, 커패시터만 있었다. 저항, 인덕터, 다이오드, 전원, BJT, 연산 증폭기, XOR, 플립플롭이 없어 모델이 XOR를 NAND 4개로 풀어 썼다.
- 새 배치로 같은 ALU를 그리면 2622×1300(폭이 높이의 2배)이 되고 domino carry 단이 한 덩어리로 선이 이어져 그려진다. 내장 브라우저에서 확인했다.
- 공통 이미터 증폭기, RLC 저역 통과, 휘트스톤 브리지, 브리지 정류기, 전송 게이트, DRAM 셀, 전류 미러, 반전 증폭기, 플립플롭과 MUX가 교과서의 관례대로 그려지는 것을 같은 방법으로 확인했다(`demo/gallery.html`).

### 결정

1. 문법에 소자 `res`, `ind`, `switch`, `diode`, `zener`, `led`, `vsrc`, `isrc`, `npn`, `pnp`와 블록 `xor`, `xnor`, `opamp`, `mux`, `dff`, `latch`, `block`을 더한다. `block`은 문법에 없는 부품을 이름 붙인 상자로 쓰는 길이다. 모든 소자가 `value`를 받고, `$…$` 없이 쓴 값은 글자 그대로 보인다.
2. 예약 이름에 `VCC`(위), `VSS`, `VEE`(아래)를 더한다.
3. 소자 묶음의 배치를 하나의 방식으로 바꾼다. 노드는 높이별 가로선, 소자는 그 사이의 세로 열이다. 직렬·병렬 분해와 그에 따른 스택 그리기는 없앤다.
4. 노드의 높이는 모든 소자를 단위 컨덕턴스(커패시터는 거의 0)로 보고 위 레일 1, 아래 레일 0으로 푼 전위의 순서로 정한다. 전위가 같은 두 노드 사이의 소자는 눕혀 그린다. 위 레일이 없으면 전압원이 아래 레일에서 들어 올린 노드를, 그것도 없으면 아래 레일에서 가장 먼 노드를 위로 삼는다.
5. 레일에 닿는 단자는 긴 선을 긋지 않고 그 자리에 레일 기호를 그린다.
6. 열의 순서는 선이 다른 노드를 가로지르는 수와 가로선 길이를 줄이도록 한 번에 한 열씩 옮겨 가며 정한다. 그래도 가로지르는 곳은 가로선을 끊고 양쪽에 노드 이름을 적는다.
7. 블록과 소자 묶음은 구동 관계의 순서대로 열에 놓는다. 고리를 만드는 연결은 순서에서 빼고, 각 묶음은 그것을 받는 쪽 바로 앞 열까지 오른쪽으로 당긴다. 서로 이어지지 않은 덩어리는 따로 배치해 행으로 채운다.
8. 이웃한 열 사이의 연결은 노드마다 세로 트랙 하나를 주어 긋는다. 다른 노드의 선이나 글자와 떨어져 있다고 확인된 핀만 잇고, 나머지 핀에는 노드 이름을 적는다. 선끼리 교차는 허용하지 않는다.
9. 연산 증폭기의 출력과 입력을 잇는 2단자 소자는 증폭기 위(반전 입력)나 아래(비반전 입력)에 그린다.
10. 임베드에서 한 열로 놓인 회로는 배율 0.6 아래로 줄이지 않고 그 안에서 스크롤한다. 앞의 "한 열만 남으면 폭에 맞게 0.7 아래로도 줄인다"는 결정을 바꾼다.
11. 배치의 올바름은 세 가지로 확인한다. 서로 다른 노드의 선이 닿지 않는다. 한 노드가 여러 조각의 선으로 그려지면 조각마다 그 노드 이름이 있다. 이 둘이 대표 회로 13개와 무작위로 만든 회로 150개에서 지켜진다.
12. version을 `0.3.0`으로 올린다.

### 보류

- 종속 전원, 변압기, 7-세그먼트 같은 전용 기호. 지금은 `block`으로 쓴다.
- 두 열 이상 떨어진 연결을 선으로 잇는 것과 선의 교차. 지금은 노드 이름으로 나타낸다.
- 논리 깊이가 깊은 회로의 폭 줄이기. ALU는 열이 11개라 좁은 미리보기에서는 좌우로 스크롤해야 한다.
- 붙여 넣는 페이지의 예제와 안내 문구는 그대로다.

### 계획에서 달라진 것

- 처음에는 직렬·병렬 스택 그리기를 남기고 분해되지 않는 회로만 새 방식으로 그리려 했다. 새 방식이 NAND나 domino 게이트도 관례대로 그려서 하나로 합쳤다.
