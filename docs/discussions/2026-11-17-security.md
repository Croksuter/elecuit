# 공개 배포 보안 게이트

## 질문

- 임베드 번들을 GitHub 공개 저장소에 올리고 jsDelivr로 배포한다. 처음으로 다른 사람에게 배포하는 경로가 생기므로, 어떤 등급과 통제가 필요한가.

## 확인한 사실

- 데이터 흐름: netlist 텍스트는 사용자의 브라우저 안에서만 읽히고 그려진다. 서버, 계정, 저장소(DB)가 없고, 페이지는 입력을 그 브라우저의 `localStorage`에만 둔다.
- 밖으로 나가는 요청: 임베드 번들이 jsDelivr에서 KaTeX 스타일과 글꼴을 번들의 KaTeX와 같은 버전으로 불러온다. netlist 내용은 요청에 실리지 않는다.
- 신뢰하지 않는 입력: netlist는 LLM이 쓴 글이다. 이름은 영문자·숫자·밑줄만 허용하고, 진단 문구는 `textContent`로 넣고, 수식은 KaTeX가 기본 설정(`trust` 꺼짐)으로 그린다.
- 산출물: `dist/elecuit.js`에 로컬 경로, 소스맵, 비밀값이 없다. 외부 주소는 jsDelivr의 KaTeX 경로 하나다.
- `gitleaks git --redact .`가 기존 커밋에서 누출을 찾지 못했고, `npm audit --omit=dev`는 0건이다.
- 커밋 작성자 이메일은 GitHub 주소이고 개인 메일이 아니다.

## 등급

- S1. 노출이 "타인에게 배포하는 앱"이라 S1이고, 데이터(없음), 권한(없음), AI 흐름(모델 호출 없음)은 S0이다.

## 통제

1. 입력 주입: 이름 형식 제한, 진단의 `textContent` 출력, KaTeX `trust` 꺼짐. 주입 시도를 T1 테스트로 막는다.
2. 공급망(우리 번들): 번들 주소는 GitHub 저장소의 태그를 따른다. 저장소 쓰기 권한을 가진 계정이 곧 배포 권한이므로, GitHub 계정의 2단계 인증을 통제로 둔다(사용자 확인 필요).
3. 공급망(의존성): 버전을 고정하고 lifecycle script 없이 설치했다. lockfile이 바뀌면 `npm audit --omit=dev`를 본다.
4. 비밀값: 커밋 전 gitleaks로 스테이징된 변경을 본다.
5. 산출물 일치: 태그를 달기 전 다시 빌드해 커밋된 번들과 차이가 없는지 본다.

## 남은 위험 (승인 대기)

- 템플릿 주소가 `@0.1` 범위라서 0.1.x 태그를 새로 올리면 이미 배포된 템플릿에도 자동으로 반영된다. 수정이 쉽게 퍼지는 대신, 계정이 탈취되면 악성 번들도 같은 경로로 퍼진다. ChatGPT Canvas는 격리된 미리보기 안에서 실행하므로 영향은 그 미리보기로 한정된다.
- KaTeX 스타일과 글꼴은 jsDelivr를 신뢰한다. 무결성 해시(SRI)는 걸지 않았다.

## 보류

- 사용자 승인: 등급 S1과 위 남은 위험.
- 라이선스 파일: 공개 저장소에 어떤 라이선스를 둘지 정하지 않았다.
